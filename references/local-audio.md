# 本地音频识别与待核候选

有视频或音频时，优先使用本机多语言语音识别为对白建立候选，流程不需要配置 API Key。准备可运行 `faster-whisper` 的 Python 环境及已下载到本机的多语言 CTranslate2 模型目录；模型和依赖的首次取得可能需要联网，使用前检查可用空间和运行条件。GPU 可用时使用 CUDA，环境不匹配则可改用 CPU；不要假定设备可用或估计运行速度。模型必须由调用者指定为已有本地目录，识别不自动下载模型或请求云端接口。

```text
python scripts/local_audio.py transcribe <音视频路径> --model <本地模型目录> --out <新候选JSON路径> --language ja --device cpu --compute-type int8
```

例子中的 `ja` 只适用于已确认的日语；实际按片源选择语言，不确定时省略 `--language` 使用模型的语言检测结果作为候选，而非最终结论。可选 `--device cpu` 或 `--device cuda`；计算类型可选 `auto`、`int8`、`float16` 或 `int8_float16`，必须与实际硬件兼容。指定模型、识别器和设备后运行，将候选输出保存到任务目录，保留输入来源、模型、请求设置和时间戳；失败时检查报错，不替换原字幕或自动将失败当成无对白。

首次使用时，需要单独准备 Python 依赖和本地模型；发布包不含模型权重，也不会自动下载。以下示例在用户选择的工作目录运行，使用 Python 3.10 及以上、隔离环境与公开的多语言 `Systran/faster-whisper-small` 模型；按需更改模型目录，不要将模型、依赖或片源写入 skill 安装目录：

```text
python -m venv .venv-subtitles
```

Windows PowerShell 中，使用该环境的 Python（其他系统使用 `.venv-subtitles/bin/python`）：

```text
.\.venv-subtitles\Scripts\python.exe -m pip install "faster-whisper==1.2.1" "av==16.1.0"
.\.venv-subtitles\Scripts\python.exe -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='Systran/faster-whisper-small', local_dir='models/faster-whisper-small')"
```

依赖与公开模型首次获取需要联网，模型文件约 486 MB；下载前检查来源和可用空间。下载后以该环境运行本 skill 的 `scripts/local_audio.py`，将模型目录传给 `--model`。以上 CPU/int8 组合已用合成语音验证；CUDA 依赖因设备而异，需单独实际验证，缺少运行库时回退 CPU。示例依赖组合曾发现 PyAV 19 与 faster-whisper 1.2.1 不兼容，故固定 PyAV 16.1.0；环境不可用时报告具体缺失项，不静默下载或切换为网络服务。候选输出路径需要支持创建硬链接的本地文件系统。

输出的 `local_asr_candidates` JSON 包含输入路径、大小和 SHA-256、模型目录及识别参数；`segments` 每段包含 ID、起止毫秒、文本和 `candidate_unverified` 状态，`review.status` 为 `pending`。这是独立候选文件，不会自动写入已有 records 或替换任务数据；须按实际情况手动整理到台账。模型目录须包含 `model.bin`、`config.json` 和 `tokenizer.json`，`preprocessor_config.json` 为可选；必需文件不完整时补齐后重试。

脚本没有选择音轨的参数；检测到多音轨输入会拒绝处理。对于多音轨视频，先用本地媒体工具探测音轨并提取用户要处理的音轨，再将提取的音频文件作为脚本输入；记录其与视频的时间对应关系和来源。模型检测到的语言不能证明处理的是用户指定的音轨，无法确认时保持待核。

**时间基准：**识别结果的起止时间从所输入音频流的解码起点计，不能直接假定等于视频时间轴。提取音轨时记录源文件、所选音轨、提取方式及已知时间偏移；使用片头、中段和片尾的实际音画锚点核对时间对应关系。若存在变速、剪辑断点或不一致的偏移，需另行分段对齐；此脚本不自动校时，也不证明识别时码已与视频同步。

1. 根据候选的原文和时间，结合其他独立来源建立 [来源台账](coverage.md)，用稳定 ID 保存来源、范围和候选文字。新候选是待核项；记录涉及的实际音轨和来源，不从生成后的字幕反向制造“完整清单”。
2. 以对应原语言及场景上下文翻译为简体中文，结合前后对白和术语进行第二轮语义复核。候选文件不会自动翻译或证明译文正确。翻译可由当前宿主模型执行：若宿主是云端，提交给它的文本可能离开本机，不能将整个流程称为离线；用户要求纯本地时必须使用实际可用的本地翻译能力。
3. 有真实听音能力及片源时，按任务范围核对原声，尤其是低声、重叠对白、歌曲、片头片尾、语种切换和识别边界；对疑点记录时间、候选和依据。检查识别空白及画面文字，不能因模型没输出而认定无对白或无画面字。ASR 不会识别画面文字，需要独立检查画面。
4. 保持识别输出和需核事项为待核；不能把模型结果、置信度或多模型一致自动写为 `verified`、实际听辨扫描完成或 coverage.ready。无法实际听辨/看画面时如实保留未核范围；所需核验未完成时遵守草稿与最终交付限制。

转写本身在本机处理音频；首次安装依赖、取得模型，或将文本交给云端宿主翻译属于不同的网络步骤。模型可能误识背景音乐、幻听、漏识短句，语言检测和时间戳也可能错误；脚本和台账无法保证全片无遗漏或取代真实音画核对。
