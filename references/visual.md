# 字体自选与剧情画面文字

## 字体与预设

`style` 按语言分别配置 font_en、font_zh、font_onscreen 和字号；1080p 默认分别为 42、46、40，描边 1.5、底部边距 60，导出时按视频高度比例缩放。这些是第一版起点，真实画面预览决定最终字号。保持白色、无衬线、细黑描边和舒适行长；1080p 数字不是所有分辨率的固定值。

运行 `python scripts/fonts.py list`；可用 `--dir` 指定其它字体目录，目录不会自动加载外部字体到播放器。运行 `check --font 实际字体文件 --face 0 --text UTF8文本文件 --report 检查结果.json` 检查文字覆盖。TTC 用 face 指定实际字体索引，候选字体家族名和文件名可能不同。覆盖检查不等于视觉样式一致；别的机器或播放器缺字体可能替换字体。第一版不内嵌/分发字体文件，用户提供字体时按任务约定处理。

用户未选择时采用任务已有预设或可用的简洁无衬线字体；字体缺失时记录替代，中文需覆盖实际字形。需要选择时提供少量可用候选与同一句预览，让用户比较。个人偏好由任务配置保存，可在下一任务复制 style；不把某一作品的选择强制推广到全部任务。

用真实视频帧渲染 ASS，至少检查普通对白、英文长句、中文长句、两人对话和文字拥挤镜头。FFmpeg 可用时通过参数数组调用 filters 的 subtitles/ass，正确转义滤镜内路径（Windows 盘符/反斜线需特别处理）；不要构造混合 shell 命令。SRT 的字体由播放器控制，不能承诺和 ASS 完全相同。

## 画面文字判断与核对

从场景切换、文字变化与用户指定镜头收集候选。优先书信、短信、公告、关键文件、身份标识、剧情线索；装饰性标语与反复出现而无新信息的文字可标明省略理由。不是逐帧把所有背景文字塞进字幕。

保存可核对的截图、源视频时间与区域；多帧核对 OCR，分别记录识别和译义状态。模糊、遮挡、缺字明确用缺失标记并附待核项，不能按剧情补全。关键书信将所有可辨读内容保存为 onscreen.full_en/full_zh，本段所对应的原文/译文写 en/zh，必要时分多个 cue。`onscreen.source_region` 用归一化坐标 `[x,y,w,h]` 标明视频原文字区；`onscreen.region` 是译文字幕的显示区域，导出按它定位。这两个区域可不同，显示位置应避开原文、主角脸、重要画面及对白。

默认画面文字只显示中文，用户可改 `display_mode: bilingual`。ASS 单独事件样式及位置；SRT 以时间边界组合并加 `【画面文字】` 标识，存在对白同时出现时依旧保留双方内容。该降级会增加行数，需重新检查阅读速度。ASS 百分秒与 SRT 毫秒可能相差不足 10ms，超过此范围不能当格式差异忽略。

完整书信放随片的文字全文说明，注明对应镜头、可辨范围与未读部分。如果视频瞬间出现完整文本，不应假定观众能读完全部双语；字幕分段、显示时段与全文附录的分工需明示。不得静默摘要成“全文翻译”或为了排版省去剧情信息。
