# 字体自选与剧情画面文字

## 字体与预设

正式制作字幕前按 [效果图与排版选择](style-selection.md) 提供字号、字体、位置三组实际效果图并取得选择。`style` 按语言分别配置 font_en、font_zh、font_onscreen 和字号；1080p 推荐分别为 42、46、40，描边 1.5，上/下边距 60，导出时按视频高度比例缩放。预设数值用于推荐，最终按用户已选配置生成；1080p 数字不是所有分辨率的固定值。

`dialogue_position` 为 `bottom`（推荐）、`middle` 或 `top`，`dialogue_align` 为 left/center/right（默认 center），组合为九宫格位置。底部使用 `margin_bottom`，顶部使用 `margin_top`，左右对齐使用 `margin_side`；三种边距默认 60，随分辨率缩放。middle 将固定容量的双语带整体置于画面中部，不把每句文本高度用作居中依据。另可提供 bottom 边距 120 的偏高预设。英语和中文可分别选字体、字号，用户也可指定边距；画面文字继续使用独立样式和 region。字号、字体、位置或边距变化后重新生成综合效果图、保存确认及哈希，并标记视觉验收与交付失效，不能为避挡擅改已选设置。

对白和歌词的 ASS 固定预留英文、中文语言带。`dialogue_en_lines`、`dialogue_zh_lines` 默认各为 2，表示语言带的行容量，取 1–8 的整数；`dialogue_line_height` 默认 1.35，表示字号对应的预留行高倍率，取 1–3，不随分辨率缩放；`dialogue_gap` 默认 8，是两种语言间的 1080p 基准间距，随视频高度缩放。容量与倍率只决定预留空间，不会缩小字体或裁掉内容，须按实际字体渲染结果调整。

每条对白/歌词导出为起止时间相同的 EN、ZH 两个事件；left/center/right 分别使用 EN `\an1/\an2/\an3` 固定英文带底边，ZH `\an7/\an8/\an9` 固定中文带顶边，两种语言共用已选水平锚点。每句行数变化时不重算语言位置：英文增加行时向上展开，中文增加行时向下展开。保留 `WrapStyle: 0` 自动换行；显式换行超过容量会由 lint 报错，自动换行后的实际行数、字体实际行高和描边仍必须真实渲染检查。任一种语言超容量、横向越出安全区或垂直超出语言带时，调整断句/换行或任务排版配置后重新验收，不能靠移动单句锚点消除跳动。

真正同期的对白/歌词使用静态槽位：基础槽位位于用户选定区域，bottom/middle 的额外槽位向上，top 的额外槽位向下；一条 cue 从出现到消失保持同一槽位，另一条进出时不将仍显示的 cue 换槽。槽位之间同样按固定容量预留高度，并核对最外侧槽位、人物和画面文字的遮挡；不能把非预期时间轴重叠仅当作排版问题。

运行 `python scripts/fonts.py list`；可用 `--dir` 指定其它字体目录，目录不会自动加载外部字体到播放器。运行 `check --font 实际字体文件 --face 0 --text UTF8文本文件 --report 检查结果.json` 检查文字覆盖。TTC 用 face 指定实际字体索引，候选字体家族名和文件名可能不同。覆盖检查不等于视觉样式一致；别的机器或播放器缺字体可能替换字体。第一版不内嵌/分发字体文件，用户提供字体时按任务约定处理。

候选字体必须真实安装或在渲染器可用，并通过样例和实际字幕的字形覆盖检查；可用组合不足时少给选项，不虚构、不自动下载或安装。已选字体缺失或被替代时记录实际情况，提供替代组合效果图并取得新选择，不能静默换字体。个人偏好保存在任务配置；新一批提供“沿用上次（推荐）”及“调整”的效果图供确认，同批已确认连续集可按范围复用。

用真实视频渲染 ASS，检查普通对白、英文长句、中文长句、两人同期对白和文字拥挤镜头，确认每种语言实际行数与行高不超预留容量且横向、垂直不溢出。诊断位置跳动还须连续播放长短句、多行切换、重叠对白进出，以及片头、中段、末尾的片段；单帧能发现遮挡，不能证明切换时位置稳定。记录渲染器/播放器、实际字体、片段范围和结果。FFmpeg 可用时通过参数数组调用 filters 的 subtitles/ass，正确转义滤镜内路径（Windows 盘符/反斜线需特别处理）；不要构造混合 shell 命令。SRT 的字体、定位和自动换行由播放器控制，不能承诺固定语言坐标或与 ASS 完全相同。

## 画面文字判断与核对

按 [coverage.md](coverage.md) 从原片逐段画面复查、场景切换、文字变化与用户指定镜头收集候选，独立于现有字幕保存稳定 source item ID、时段和证据；OCR 未检测到或画面暂无 cue 都不能作为无文字依据。优先书信、短信、公告、关键文件、身份标识、剧情线索；装饰性标语或无新信息的重复文字可排除，但每个已收集候选仍须保留理由与证据。复查快速出现/消失、复杂文件和片头末尾画面文字；实际复查区间记在 visual scans，不把抽帧/OCR覆盖率冒充全片已审看。

保存可核对的截图、源视频时间与区域；多帧核对 OCR，分别记录识别和译义状态。模糊、遮挡、缺字明确用缺失标记并附待核项，不能按剧情补全。关键书信将所有可辨读内容保存为 onscreen.full_en/full_zh，本段所对应的原文/译文写 en/zh，必要时分多个 cue，并将同一来源 item 链接到所有相关段落。检查段落组合与可辨全文是否对应，不能只因其中一条 cue 存在或时间重合就将整封信判为完成。`onscreen.source_region` 用归一化坐标 `[x,y,w,h]` 标明视频原文字区；`onscreen.region` 是译文字幕的显示区域，导出按它定位。这两个区域可不同，显示位置应避开原文、主角脸、重要画面及对白。

默认画面文字只显示中文，用户可改 `display_mode: bilingual`。ASS 仍使用单个独立定位的画面文字事件，不占用对白的固定语言带；SRT 以时间边界组合并加 `【画面文字】` 标识，存在对白同时出现时依旧保留双方内容。该降级会增加行数，需重新检查阅读速度。ASS 所有边界就近取整到百分秒，与 SRT 毫秒的单个边界误差最多 5ms；相同边界使用相同结果，不因取整制造相邻记录重叠。

完整书信放随片的文字全文说明，注明对应镜头、可辨范围与未读部分。如果视频瞬间出现完整文本，不应假定观众能读完全部双语；字幕分段、显示时段与全文附录的分工需明示。不得静默摘要成“全文翻译”或为了排版省去剧情信息。
